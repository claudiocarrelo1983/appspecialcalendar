Android native startup fix after APK 22:
The installed react-native-webview Android WebMessageListener passes sourceOrigin as onMessage.url, not the complete page URL.
The old strict page-URL comparison discarded valid snapshots, leaving Administration on its timeout error screen.
The bridge now includes the actual document URL and a native navigation generation ID; origin-only and full-URL transports are supported while stale and foreign-company messages remain rejected.
The outer shell changes client/admin state only for accepted document messages and initializes clients with the actual document URL.
Startup failures now expose a bounded reference code for diagnosis without cookies, tokens or account data.
A regression test reproduces the original failure, and an integrated injected-script test verifies the Android-style handshake.
These changes are local source changes until explicitly delivered in a new build/update. Do not start an EAS cloud build without the user's explicit request.
